### Summary

- Defects found: **21/21** explorations of a defective variant.
- False alarms: **0/9** explorations of a correct variant.
- Throughput: 35 (30–55) runs per second (each run starts a fresh local portal).
- Unhandled findings are `KeyError`s after an `invalid_output` fault in every client but `journaled`. Oracle-only findings come from `duplicate`: the portal is not idempotent, so a duplicated delivery stores two applications that no client can prevent or see in its trace.

## Instrumentation overhead

| Measure | Value |
|---|---|
| Trivial in-process call, direct | 0.07 µs |
| Same call recorded through a `Session` | 13.98 µs |
| HTTP lookup to the local portal, direct (median of 300) | 0.866 ms |
| Same lookup recorded (median of 300, alternated) | 0.918 ms (+6.0%) |
| Fixed recording cost as a share of that HTTP call | 1.6% |
| Memory per recorded event (small request) | 1105 bytes |
| SQLite disk per stored event (small request) | 340 bytes |

The per-call cost of recording (normalising, dependency inference, the event itself) is fixed, and small next to even a local HTTP call. The measured direct-versus-recorded difference on the HTTP call is larger than that fixed cost; the rest is variation between calls, which alternating 300 samples and taking medians reduces but does not remove.
